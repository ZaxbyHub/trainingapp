# Sidecar slice pins: the repo's own requirements.txt (the sidecar IS the
# existing pipeline packaged) plus PyInstaller. Built in a dedicated venv so
# the measured build matches the repo pins, not the dev env's drift.
-r ../../requirements.txt

# requirements.txt does not pin torch (sentence-transformers pulls it). The
# newest generation (torch 2.14) FAILS to initialize under PyInstaller onedir
# on Windows (c10/torch_cpu DLL init, WinError 1114) even with OpenMP + DLL
# search-path mitigation; 2.2.2 is the generation the repo's app_gui.spec
# PyInstaller flow ships successfully. Recorded in docs/adr/0003.
torch==2.2.2

# torch 2.2.2 is a numpy-1-generation build: with numpy 2.x the frozen build
# segfaults at `import chromadb` (compiled deps in the numpy-1 ABI). Recorded
# in docs/adr/0003.
numpy<2

# onnxruntime (pulled by chromadb's default-embedding import chain) at the
# newest generation segfaults the frozen build at `import onnxruntime`;
# 1.17.3 is the matched-era build that initializes cleanly under PyInstaller.
# Recorded in docs/adr/0003.
onnxruntime==1.17.3
